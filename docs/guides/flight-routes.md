# راهنمای مرحله‌ای گرید؛ نمونهٔ مسیرهای پروازی

این سند منطق فایل [flight-routes.json](./flight-routes.json) را برای ارائه توضیح می‌دهد. هدف این است که متن و ترتیب راهنما از کد رابط کاربری جدا بماند و بتوان آن را برای هر گرید متناسب با کار همان صفحه تعریف کرد.

## ایدهٔ اصلی

برای هر لیست، یک شیء JSON شامل مشخصات راهنما و آرایه‌ای از مراحل تعریف می‌شود. هر مرحله متن خودش را دارد و با `target` به یک بخش واقعی از صفحه وصل می‌شود. گرید راهنما را می‌سازد و نمایش می‌دهد؛ JSON تعیین می‌کند چه چیزی، با چه ترتیبی و دربارهٔ کدام بخش توضیح داده شود.

این تقسیم مسئولیت باعث می‌شود برای معرفی یک لیست تازه، معمولاً فقط JSON همان لیست و در صورت نیاز نگاشت targetهای اختصاصی آن صفحه اضافه شود؛ کد نمایش راهنما بین گریدها مشترک می‌ماند.

## مسیر اجرا در پروژه

1. در استودیوی نمونه، داده‌های لیست به این JSON راهنما متصل می‌شوند. در پروژهٔ مصرف‌کننده می‌توان همین JSON را از API یا دیتابیس دریافت کرد.
2. هنگام ساخت گرید، JSON در گزینهٔ `guide` قرار می‌گیرد و `culture.template` برابر `template4` است. Templateهای ۱ تا ۳ این راهنما را فعال نمی‌کنند.
3. گرید پیکربندی را اعتبارسنجی می‌کند و دکمهٔ «راهنمای لیست» را کنار ابزارهای گرید قرار می‌دهد.
4. با کلیک کاربر، راهنما مرحله‌ها را به‌ترتیب نشان می‌دهد، target هر مرحله را در همان گرید پیدا می‌کند و آن را برجسته می‌کند.
5. با بستن، رد کردن، پایان، فشردن Escape یا حذف گرید، پنجره و شنونده‌های موقت پاک می‌شوند و تمرکز صفحه به دکمهٔ شروع برمی‌گردد.

راهنما خودکار باز نمی‌شود و روی target کلیک نمی‌کند؛ فیلتر، انتخاب ردیف و داده‌های گرید را هم تغییر نمی‌دهد.

### نسخهٔ موبایل

همین JSON در نمای موبایل هم استفاده می‌شود؛ نیازی به مراحل یا targetهای جداگانه نیست. از کارت «نسخه موبایل» داشبورد یا حالت موبایل گرید، دکمهٔ «راهنمای لیست» را بزنید. کادر راهنما در پیش‌نمایش تلفن، کنار هدف و در محدودهٔ همان پیش‌نمایش قرار می‌گیرد؛ در تلفن واقعی هم با عرض صفحه سازگار است. برای هدف‌های کوچک، نشانگر اتصال محل هدف را مشخص می‌کند. اگر ردیف و توضیح با هم در صفحهٔ کوتاه جا نشوند، کادر پایین صفحه قرار می‌گیرد و متن توضیح داخل آن قابل اسکرول می‌شود؛ دکمه‌های جابه‌جایی در دسترس می‌مانند.

## ساختار JSON

| فیلد | کاربرد |
| --- | --- |
| `schemaVersion` | نسخهٔ ساختار JSON؛ برای این قرارداد باید `2` باشد. نسخهٔ ۲ نوع `id` را عددی می‌کند و `lid` را اضافه می‌کند. |
| `id` | شناسهٔ عددی مثبت و پایدار آموزش در ریشهٔ JSON؛ برای نسخه‌های ترجمه‌شدهٔ یک آموزش، همین شناسه را نگه دارید. این تغییر به `steps[].id` مربوط نیست؛ شناسهٔ مراحل همچنان رشته‌ای و در همان آموزش یکتا است. |
| `lid` | شناسهٔ عددی مثبت زبان آموزش؛ در نمونهٔ فارسی مقدار `1` است. مقدار را مطابق شناسهٔ زبان در سامانهٔ خودتان تنظیم کنید. |
| `revision` | شمارهٔ بازبینی محتوا؛ با تغییر معنادار متن یا مراحل افزایش داده می‌شود. در نسخهٔ فعلی سابقهٔ مشاهده یا تکمیل کاربر را ذخیره نمی‌کند. |
| `title` | عنوان کلی راهنما و نام دسترس‌پذیر پنجره. |
| `steps` | مراحل، به همان ترتیبی که در آرایه آمده‌اند. |

هر عضو `steps` این فیلدها را دارد:

| فیلد | کاربرد |
| --- | --- |
| `id` | شناسهٔ یکتای مرحله در همین راهنما. |
| `target` | نام منطقی بخشی از صفحه که باید برجسته شود؛ selector یا کد JavaScript نیست. |
| `title` | عنوان کوتاه مرحله. |
| `description` | توضیح و راهنمای عملی مرحله. |
| `optional` | اگر `true` باشد، مرحله‌ای که target آن در نمای فعلی وجود ندارد از راهنما کنار گذاشته می‌شود. اگر حذف شود یا `false` باشد، مرحله باقی می‌ماند و در صورت نبود target پیام در دسترس نبودن آن بخش نشان داده می‌شود. |

شناسه‌ها یکتا هستند؛ تعداد مراحل، طول متن‌ها و قالب شناسه‌ها هم اعتبارسنجی می‌شود. متن‌ها به‌صورت متن ساده نمایش داده می‌شوند، نه HTML.

در دیتابیس، اگر هر ترجمه یک رکورد جداست، روی `(id, lid)` ایندکس مرکب یکتا بگذارید؛ `id` آموزش را مشخص می‌کند و `lid` نسخهٔ زبانی را. `id` و `lid` در JSON عدد هستند، نه رشته.

```json
{
  "schemaVersion": 2,
  "id": 1,
  "lid": 1,
  "revision": 2
}
```

## Targetها چطور وصل می‌شوند؟

`target` یک نام قراردادی است، نه آدرس DOM. برای بخش‌های معمول گرید، خود Template 4 نگاشت آماده دارد و آن را فقط در محدودهٔ همان گرید جستجو می‌کند:

| Target | عنصر موردنظر در گرید |
| --- | --- |
| `list.header` | محتوای هدر ساخته‌شده با `headerMaker`؛ اگر هدر تعریف نشده باشد، نوار ابزار خود گرید. |
| `list.search` | جستجوی گرید. |
| `list.filters` | کنترل فیلتر. |
| `list.row` | یک ردیف قابل‌مشاهده؛ در نمای موبایل، کارت معادل آن. |
| `list.row.checkbox` | چک‌باکس انتخاب ردیف. |
| `list.bulk.actions` | عملیات انتخاب گروهی؛ در نمونه فعلی پاک‌کردن انتخاب‌ها. |
| `list.row.actions` | دکمهٔ عملیات همان ردیف، مثل سه‌نقطه. |
| `list.pagination` | نوار صفحه‌بندی، وقتی صفحه‌بندی فعال باشد. |

برای عنصری بیرون از گرید، برنامه باید یک resolver مورداعتماد در `guideTargets` ثبت کند؛ مثلاً `page.create`. JSON فقط نام آن را درخواست می‌کند. بنابراین اضافه‌کردن نامی مثل `page.create` به‌تنهایی کافی نیست و باید آن target در برنامه نگاشت شود.

### نمونهٔ کامل: دکمهٔ افزودن پرواز بیرون گرید

این مرحله را به آرایهٔ `steps` اضافه کنید:

```json
{
  "id": "create-flight",
  "target": "page.create-flight",
  "title": "افزودن پرواز جدید",
  "description": "برای ثبت یک مسیر پروازی تازه، دکمهٔ افزودن پرواز را انتخاب کنید.",
  "optional": true
}
```

در صفحه، دکمه را با یک شناسهٔ پایدار مشخص کنید:

```html
<button id="create-flight" type="button">افزودن پرواز</button>
```

و هنگام ساخت گرید، همان نام target را به عنصر وصل کنید:

```ts
const options = {
  guide: flightRoutesGuide,
  guideTargets: {
    "page.create-flight": () => document.querySelector<HTMLElement>("#create-flight"),
  },
};
```

نام `page.create-flight` باید در JSON و `guideTargets` دقیقاً یکسان باشد. چون این مرحله `optional` است، اگر دکمه در آن صفحه یا نمای کاربر حاضر نباشد، مرحله از تور کنار گذاشته می‌شود. resolver فقط عنصر را برای برجسته‌سازی پیدا می‌کند؛ راهنما خودش دکمه را فعال نمی‌کند.

در همین استودیو، target بیرونی `page.create` به دکمهٔ «دادهٔ جدید» نگاشت شده است. آن دکمه برای ساخت dataset است، نه ثبت پرواز؛ بنابراین نمونهٔ بالا یک الگوی عمومی برای صفحه‌ای است که واقعاً دکمهٔ افزودن پرواز دارد.

## مراحل نمونهٔ مسیرهای پروازی

در [flight-routes.json](./flight-routes.json)، مراحل از معرفی ماهیت لیست شروع می‌شوند و بعد به کار واقعی کاربر می‌رسند:

1. `list.header`: تفاوت لیست مسیرها با رزرو و بلیت مسافر را مشخص می‌کند.
2. `list.row`: توضیح می‌دهد هر ردیف یک مسیر است و از مبدأ/مقصد، ایرلاین، کد و وضعیت برای تشخیص آن استفاده می‌شود.
3. `list.row.actions`: کار سه‌نقطه را توضیح می‌دهد. در پیاده‌سازی فعلی، سه‌نقطه جزئیات همان مسیر را باز می‌کند؛ ویرایش یا حذف انجام نمی‌دهد.
4. `list.search`: یک مثال واقعی مثل `EK-978` یا نام مقصد/ایرلاین می‌دهد.
5. `list.filters`: ترکیب فیلتر ایرلاین و وضعیت با جستجو را نشان می‌دهد.
6. `list.row.checkbox`: روشن می‌کند انتخاب، مربوط به خود مسیر است و به‌تنهایی آن را حذف، لغو یا غیرفعال نمی‌کند.
7. `list.bulk.actions`: فقط پاک‌کردن انتخاب‌ها را معرفی می‌کند؛ عملیات گروهی حذف یا تغییر وضعیت در نمونه وجود ندارد.
8. `list.pagination`: جابه‌جایی بین صفحه‌های نتایج فعلی را شرح می‌دهد.

مراحل ردیف، عملیات، انتخاب، عملیات گروهی و صفحه‌بندی اختیاری‌اند؛ چون ممکن است با فیلترها، تنظیمات یا نمای کوچک صفحه در دسترس نباشند. مرحله‌های جستجو و فیلتر جزو مسیر اصلی آموزش‌اند.

## الگوی افزودن به یک لیست دیگر

1. برای هر راهنمای جدید یک `id` عددی مثبت تعیین کنید؛ ترجمه‌های همان راهنما همان `id` و `lid` متفاوت دارند. `revision: 1` و متن‌های همان زبان را قرار دهید.
2. از targetهای آمادهٔ گرید استفاده کنید؛ نامی را انتخاب نکنید مگر واقعاً در گرید یا نگاشت صفحه ثبت شده باشد.
3. مرحله‌هایی را که در بعضی نماها/تنظیمات غایب‌اند با `optional: true` مشخص کنید.
4. JSON را به dataset وصل کنید تا هنگام ساخت گرید به `options.guide` برسد.
5. در Template 4 دکمهٔ راهنما را بزنید و مسیر مراحل را در دسکتاپ و موبایل بررسی کنید.

برای شخصی‌سازی این نمونه، متن را در `flight-routes.json` تغییر دهید و در صورت تغییر محتوای منتشرشده `revision` را افزایش دهید. برای زبان دیگر، رکوردی با همان `id` و `lid` همان زبان بسازید. تا زمانی که target جدید در گرید یا `guideTargets` ثبت نشده، در JSON برای آن مرحله تعریف نکنید.

## نکته برای ارائه

«محتوا داده‌محور است، اما اجرای امن و پیدا کردن اجزای واقعی صفحه با کامپوننت BasisCore انجام می‌شود. JSON رفتار گرید را تغییر نمی‌دهد؛ فقط متن راهنما، ترتیب مراحل و targetهای نام‌گذاری‌شده را تعیین می‌کند. برای هر لیست می‌توان محتوای متناسب خودش را داد و در عین حال یک تجربهٔ راهنمای مشترک داشت.»
